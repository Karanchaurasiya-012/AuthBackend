Step 1 — Check Docker + host ports

DONE

Commands:

docker --version
docker compose version
ss -ltnp | grep -E ':8080|:5432'
ls -la keys/

Result:

  • Docker 29.1.3 available
  • Docker Compose v5.3.1 available
  • JWT keys present: keys/private.pem, keys/public.pem
  • Maven wrapper present: mvnw
Conflict found: Host PostgreSQL already listening on 127.0.0.1:5432.
Why it matters: If compose maps 5432:5432, Docker cannot bind host port 5432.
Fix applied: In docker-compose.yml, map host 5433 → container 5432. Backend still connects internally as postgres:5432. Host tools use localhost:5433.

Step 2 — Add Docker files

DONE

Created:

  • .dockerignore — keep build context small; exclude .env, target/, docs
  • Dockerfile — multi-stage: Temurin 17 JDK build → Temurin 17 JRE run
  • docker-compose.yml — services postgres + backend
  • .env.docker.example — notes for Docker DB host/ports

Why multi-stage Dockerfile? Build needs JDK/Maven; runtime only needs JRE + JAR (smaller image).

Why compose overrides DB_URL? Inside Docker network, DB hostname is service name postgres, not localhost.

DB_URL=jdbc:postgresql://postgres:5432/auth_db
JWT_PRIVATE_KEY_PATH=/app/keys/private.pem
JWT_PUBLIC_KEY_PATH=/app/keys/public.pem
Conflict anticipated: Host keys/private.pem is mode 600. A non-root container user cannot read it when mounted.
Fix applied: Runtime image runs without dropping to a non-root user for local Docker. Documented for later hardening with proper secret mounts.
